# Разбор прайсов поставщиков

Единый механизм проекта: `src/utils/priceSkill.ts`. Не писать отдельный парсер под файл и не просить пользователя назначить все колонки.

## Вызов

Из программы и из агента почты одна функция:

```typescript
import { normalizePriceFile } from "./src/utils/priceSkill";

const documents = await normalizePriceFile(file, supplierName, savedMapper);
```

`savedMapper` — ранее сохранённая структура этого поставщика или `null`. Файл может прийти с диска или из вложения письма.

## Результат

Каждый документ уже в единой строке прайса:

1. Наименование
2. Цена
3. Штрихкод
4. Остаток
5. Единица измерения
6. Упаковка
7. Кратность

Обязательны только наименование и цена. Код или артикул поставщика сохраняется отдельно и не является идентификатором товара.

`status: "ready"` — можно сохранять. `question` — спросить только про конкретное поле, обычно какую из нескольких рабочих цен взять. Полную форму колонок не показывать.

## Как разбирать

1. Определить тип файла и вытащить таблицы. ZIP раскрывать по файлам. PDF-скан без текстовой таблицы не превращать в товары.
2. Найти лист и полосу заголовков. Шапка может быть ниже первой строки и занимать несколько строк. Служебный текст до таблицы не считать заголовком.
3. Смысл колонки решать по заголовку, синонимам и значениям вместе. Торговая марка, группа, подгруппа и категория не являются наименованием. НДС, сумма, процент скидки, заказ и количество на паллете не являются ценой и остатком.
4. Если рабочих цен несколько и ни одна не является справочной или порогом «от N», остановиться и спросить только про эти цены.
5. Пропустить группы, итоги, пустые строки и строки без положительной цены. У иерархии Excel брать строки-листья, а не родительские группы.
6. Штрихкод читать как текст: не переводить в научную запись и не отрезать ведущий ноль.
7. После успешного разбора запомнить подпись заголовков поставщика. В следующий раз проверить, что подпись та же, и сопоставить колонки по названиям, а не по номерам. Если подпись изменилась, разобрать файл заново.

Подробности структур, которые уже встречались, лежат в [reference.md](reference.md).
