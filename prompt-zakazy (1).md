# Промпт для создания системы управления заказами поставщикам

Создать полнофункциональное веб-приложение для управления заказами у поставщиков с автоматическим сопоставлением номенклатуры на React 18 + TypeScript + Vite.

## 🎯 ОБЩЕЕ ОПИСАНИЕ

Система позволяет компании загружать прайсы от разных поставщиков, автоматически сопоставлять товары с внутренним каталогом из 1С, сравнивать цены и формировать оптимальные заказы.

Все данные хранятся в localStorage браузера. Приложение полностью работает без сервера.

## 📑 СТРУКТУРА ПРИЛОЖЕНИЯ - 4 ОСНОВНЫХ ВКЛАДКИ

### ✅ ВКЛАДКА 1: "СЕГОДНЯ" (Setup Tab)
**Назначение:** Первоначальная настройка и загрузка файлов

#### Функции:
1. **Загрузка прайса поставщика**
   - Кнопка "Загрузить прайс вручную" (развёрнутая форма)
   - Поле для выбора файла (Excel, CSV, ODS, Google Таблицы)
   - Поле для ввода имени поставщика (если нет в файле)
   - Поле выбора строки с заголовками (по умолчанию 1)
   - Сообщение: "Файл может быть в любом привычном виде: программа сама найдёт название и цену"

2. **Маппинг колонок (первый раз)**
   - Если формат прайса новый → показывается форма маппинга
   - Выпадающие списки для выбора колонок:
     - Название товара (обязательно)
     - Цена (обязательно)
     - Штрихкод (опционально)
     - Код товара (опционально)
     - Единица измерения (опционально)
   - Предпросмотр: показать первые 5-10 строк таблицы
   - Кнопка "Загрузить так" → сохраняет маппинг для этого поставщика
   - На следующий раз такой же формат загрузится автоматически

3. **Загрузка каталога товаров (один раз)**
   - Статус загрузки каталога (кол-во товаров)
   - Кнопка "Обновить номенклатуру из 1С" (видна только если каталог уже загружен)
   - Сообщение: "Список товаров из 1С. Его загружают один раз, сопоставления остаются"
   - Файл может быть Excel или CSV с колонками: Код | Название | Единица

#### Внешний вид:
- Карточки (card design)
- Светлые кнопки для дополнительных действий
- Серая помощь-текст для подсказок

---

### 💰 ВКЛАДКА 2: "ПРАЙСЫ" (Prices Tab)
**Назначение:** Просмотр загруженных прайсов

#### Функции:
1. **Сводка по поставщикам**
   - Список всех загруженных поставщиков
   - Для каждого: кол-во товаров, дата загрузки
   - Кнопка "Показать прайс" → открывает детальную таблицу

2. **Детальная таблица прайса**
   - Колонки: 
     - Номенклатура поставщика (18%)
     - Цена (11%)
     - Наша номенклатура (20%) - сопоставленный товар
     - Состояние (8%) - статус сопоставления
   - Поле поиска вверху (ищет по названию)
   - Фильтры по статусам:
     - Все
     - Нужно решить (не сопоставлено)
     - Подтверждено (выбран товар и принято)
     - Отсутствует (отмечено как нет в каталоге)
   - Пагинация: показывать по 40 строк, кнопка "Показать ещё"

#### Цветовая индикация:
- Жёлтый фон: нужно решить
- Зелёный фон: подтверждено
- Красный фон: конфликт/отсутствует

---

### 🔀 ВКЛАДКА 3: "НОМЕНКЛАТУРА" (Matching Tab)
**Назначение:** Сопоставление товаров поставщиков с внутренним каталогом

#### Функции:
1. **Выбор поставщика и поиск**
   - Выпадающий список всех поставщиков
   - Поле поиска по названию товара (width: 360px)
   - Фильтры-кнопки:
     - Нужно решить (жёлтый)
     - Подтверждено (зелёный)
     - Отсутствует (красный)
     - Всё решено (серый)
   - Счётчик "X нужно решить, Y подтверждено"

2. **Таблица сопоставлений**
   - Колонки (фиксированные ширины):
     - Номенклатура поставщика (18%)
     - Поставщик (11%)
     - Предлагаемая наша номенклатура (20%)
     - Уверенность (8%) - процент совпадения
     - Почему (18%) - причина предложения (по коду, по названию, по штрихкоду)
     - Статус (11%) - текущий статус
     - Действие (14%) - кнопки действий
   - Пагинация: по 40 строк
   - Перенос текста (word-wrap)

3. **Алгоритм автосопоставления**
   - ✅ Точное совпадение по коду
   - ✅ Точное совпадение по штрихкоду
   - ✅ Нечёткий поиск по названию (убирает стоп-слова, ищет ключевые части)
   - ✅ Совпадение по единице измерения (kg, шт, л и т.д.)
   - ❌ Если ничего не подошло → "Нужно решить"

4. **Действия для каждого товара**
   - ✅ Кнопка "Да" (зелёная) → принять предложенный товар
   - 🔄 Кнопка "Альтернатива" (жёлтая) → предложить другой товар
   - 🔍 Кнопка "Выбрать..." → открыть модаль с поиском по каталогу
   - ❌ Кнопка "Нет в каталоге" (серая) → отметить как отсутствующее

5. **Модаль выбора товара**
   - Активируется по нажатию "Выбрать..."
   - Позиционируется ниже кнопки (position: fixed)
   - Поле поиска с placeholder "шуманит"
   - Список результатов (макс 30 товаров)
   - Поиск работает по:
     - Частям названия (слова)
     - Единице измерения
   - Клик на товар → выбирает его и закрывает модаль
   - Клик вне модали → закрывает её

#### Синтаксис поиска в модали:
- "ALLEY" → ищет товары с ALLEY в названии
- "шуманит" → ищет товары со словом "шуманит"
- "500g" → ищет товары с "500g" в названии ИЛИ в единице
- Минимум 3 символа для начала поиска

### 📦 ВКЛАДКА 4: "ЗАКАЗ" (Order Tab)
**Назначение:** Формирование финального заказа с выбором лучших предложений

#### Функции:
1. **Автоматическое формирование заказа**
   - Берутся только товары с статусом "подтверждено" и "выбрано"
   - Для каждого товара показывается:
     - Название нашего товара (жирный текст)
     - Лучший вариант: поставщик и цена
     - Второй вариант (если есть): поставщик и цена (серый текст)
   - Если есть конфликты по единицам → предупреждение

2. **Выявление проблем**
   - ⚠️ Нет строки с правильной единицей → показать ошибку
   - ⚠️ Единица не совпала → показать ошибку
   - ✅ Если всё хорошо → показать карточку заказа

3. **Действия**
   - Кнопка "Подтвердить" → зафиксировать выбор поставщика на сегодня
   - Кнопка "Нет в наличии" → отметить как отсутствующее, выбрать второго поставщика

#### Ограничения:
- Показывать максимум 80 товаров
- Если нет подтвёрждённых товаров → кнопка "Собрать заказ" неактивна

## 📊 СТРУКТУРА ДАННЫХ

### AppState (localStorage key: "zakazy-state")
```typescript
interface AppState {
  // Загруженные прайсы [поставщик, название, цена, штрихкод, код, единица, файл]
  uploads: Array<{
    file: string;           // имя файла (для дедупликации)
    supplier: string;       // имя поставщика
    rows: Array<[string, string, number, string, string, string, string]>;
  }>;

  // Каталог товаров из 1С
  catalog: Array<{
    code: string;          // уникальный код
    name: string;          // название
    unit: string;          // единица
  }>;

  // Сохранённые маппинги для разных форматов
  mappers: Map<string, {
    headerRow: number;
    name: number;      // индекс колонки
    price: number;
    barcode: number;
    code: number;
    unit: number;
  }>;

  // Сопоставления товаров [ключ -> решение]
  matches: Map<string, {
    status: "need" | "confirmed" | "picked" | "missing";
    code: string;           // код нашего товара
    confidence: number;     // 0-100%
    reason: string;         // "по коду", "по названию", "по штрихкоду"
  }>;

  // Подтвёрждённые заказы на сегодня
  confirmed: Map<string, {
    supplier: string;
    price: number;
    date: string;          // дата подтверждения
  }>;

  // Товары без наличия на сегодня
  absent: Map<string, string>;  // "код|поставщик" -> "2024-01-15"

  // Отмеченные как "нет в каталоге"
  cleared: Map<string, boolean>;

  // Список просмотренных товаров (для дедупликации)
  seen: Map<string, number>;

  seenReady: boolean;
}
```

## ⚙️ ЛОГИКА И АЛГОРИТМЫ

### 1. Парсинг прайса
- Поддерживаемые форматы: .xlsx, .xls, .csv, .ods, HTML (из Google Таблиц)
- Библиотеки: `papaparse` для CSV, `xlsx` для Excel
- Если поставщик не указан в файле → используется значение из формы
- Результат: Array<[supplier, name, price, barcode, code, unit, filename]>

### 2. Автоматическое определение маппинга (первый раз)
- Анализировать заголовки колонок
- Ищет слова типа: "название", "name", "товар", "product" и т.д.
- Ищет слова типа: "цена", "price", "стоимость"
- Если не нашлось → показать форму маппинга с выпадающими списками
- Сохранить маппинг для будущих файлов этого поставщика

### 3. Сопоставление товаров (Matching)
Алгоритм работает в этом порядке:

**Фаза 1: Точные совпадения (уверенность 100%)**
- По коду товара
- По штрихкоду

**Фаза 2: Нечёткий поиск по названию (уверенность 50-90%)**
- Разбить названия на токены (слова)
- Убрать стоп-слова (и, или, в, на, по, для и т.д.)
- Ищет, чтобы все ключевые слова из прайса нашлись в названии каталога
- Если совпадает 100% слов → 90%
- Если совпадает 75% слов → 70%
- Если совпадает 50% слов → 50%

**Фаза 3: Проверка единицы измерения**
- Нормализовать единицы (kg → kilograms, г → grams и т.д.)
- Если расчётная единица конфликтует с каталогом → уверенность ↓
- Если никакой информации о единице → игнорировать

**Фаза 4: Если ничего не подошло**
- Статус: "need" (нужно решить)

### 4. Фильтры поиска
- **В таблице Прайсы:** поиск по всем полям, фильтр по статусу
- **В таблице Номенклатура:** поиск по названию + фильтр по статусу + фильтр по поставщику
- **В модали выбора:** поиск по названию и единице из каталога
- Чувствительность: регистронезависимый поиск, транслитерация опционально

### 5. Логика заказа
- Для каждого кода из каталога, если есть сопоставления:
  - Собрать все варианты поставщиков
  - Отфильтровать по правильной единице
  - Отфильтровать отсутствующие (absent) на сегодня
  - Выбрать с минимальной ценой
  - Показать второй вариант
  - Если нет вариантов с правильной единицей → ошибка
